# code-organization

How the repository is laid out and where a new thing goes. CLAUDE.md's
routing table is the short form; this file is the reasoning and the rules
behind it.

## 1. Top level

| Path                  | Purpose                                                                                                                                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/`                | All application code. Domain folders plus `app/` (Next routes) and `ui/` (components).                                                                                                                                                    |
| `scripts/`            | Operator tools: EPA install, user ingest, migrate, public sample, knowledge compile, eval-db ensure, docs check, worktree helper, auth hashing, Vercel/GitHub helpers.                                                                    |
| `evals/`              | Eval runner, cases, suites, and the committed artifacts `results.{md,json}` + `history.jsonl`. `evals/agent/` holds the Eve runtime cases, the decision cohort and their reports.                                                         |
| `agent/`              | The eve service, co-hosted by `withEve()`: the coordinator, its channel, tools, hooks, schedules and `lib/`. Not under `src/`; it builds and deploys as its own service. Distinct from `src/agent/`, the two agents' shared runtime (§2). |
| `db/migrations/`      | Postgres migrations (node-pg-migrate, plain SQL, numbered).                                                                                                                                                                               |
| `data/`               | Committed `epa-sample.csv`, provenance and `public-generations.json`; ignored source downloads and `*.db`.                                                                                                                                |
| `fixtures/`           | Static fixtures shared across tests (network recordings live next to the module that uses them).                                                                                                                                          |

## 2. `src/` domain folders

One folder per stage or subsystem. A folder holds pure logic, its injected
default callers, its types, and its tests beside the code (`x.ts` +
`x.test.ts`). Nothing in a domain folder imports from `app/` or `ui/`.

Neither agent imports the other's orchestrator: what both need — the tool
worker loop, the push channel, the settled-stage wrapper, the VIN stage —
lives in `agent/` (`docs/patterns.md §5.5`). `agent/` still reaches into
`inspector/vin.ts`, `vin-history.ts` and `research.ts` for the VIN
primitives the stage runs; those are leaves, not orchestrators. A new
dependency from one agent folder on the other's orchestrator is the thing
this layout exists to prevent.

## 3. Where does X go?

| You are adding…                   | Put it in                                                                                                                                                             |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A meaning for a code or shorthand | `src/knowledge/` (validated by `knowledge.test.ts`)                                                                                                                   |
| A parse rule                      | `src/interpret/tokenize.ts` + a case in `tokenize.test.ts` and `evals/queries.jsonl`                                                                                  |
| A new external data source        | `src/enrich/<source>.ts` with an injected fetcher and a `StageStatus`; wire in `src/pipeline/enrich.ts`                                                               |
| A new model call                  | The owning domain folder: `<Name>Caller` type, default caller with lazy SDK import, zod schema, tests with a scripted caller (`docs/llm-patterns.md`)                 |
| A rule for reading a pasted lot   | `src/assessments/intake.ts` + a case in `intake.test.ts` over `intake-fixtures/listings.ts`; the prompt lives in `intake-caller.ts` (`docs/agent-assessments.md §14`) |
| A new inspection/salvage stage    | Its own file in `inspector/` or `salvage/`; `begin` + `stage` events in the orchestrator; a SPEC rule; a suite check in `evals/`                                      |
| A new page                        | `src/app/<route>/page.tsx` (server component); components in `src/ui/`; state in the URL                                                                              |
| A new API route                   | `src/app/api/<name>/route.ts`; zod-validate the body; return `StageStatus`-style errors, never stack traces                                                           |
| A pure formatting helper          | `src/ui/format.ts` (+ test)                                                                                                                                           |
| A design token or type style      | `DESIGN.md` first, then `src/app/globals.css`                                                                                                                         |
| A Postgres table                  | `db/migrations/NNNN_<name>.sql` + store method + contract test in `src/runs/store.test.ts`                                                                            |
| An operator command               | `scripts/<name>.ts` (or `.sh`) + a `package.json` script + a row in `docs/operations.md`                                                                              |
| A recurring procedure             | `docs/workflows/<name>.md`                                                                                                                                            |
| A multi-session effort            | `docs/initiatives/YYYY-MM-DD-<slug>.md`                                                                                                                               |

## 4. File conventions

### 4.1 Headers and comments

From CLAUDE.md: a file opens with a `/** … */` block (or a `//` block on
older files) stating the module's responsibility and the invariants it
owns. Inline comments state a constraint or a reason the code cannot
express, present tense, one or two sentences. Section dividers are
`// -- Name ----`. No first person, no narration of how a bug was found,
no references to sessions or reviews.

### 4.2 Naming

- Files: kebab-case (`seed-listings.ts`, `resolve-store.ts`). Tests:
  `<name>.test.ts` beside the file.
- Injected function types end in `Caller`, `Fetcher`, or `Probe`; their
  defaults are `default<Name>` and are the only place an SDK is imported.
- Orchestrators that stream end in `Stream` (`inspectCarStream`).
- Pure parsers of model output start with `parse` and take `unknown`.
- Constants that are budgets or limits are `SCREAMING_CASE` with units in
  the name (`WORKER_BUDGET_MS`, `MAX_PHOTOS`).

### 4.3 Imports

- `@/` aliases `src/` (tsconfig `paths`, vitest `alias`).
- Domain code never imports React, Next, or `app/`.
- `ui/` may import domain types and pure functions, never callers.

### 4.4 Types

- Shared cross-stage types live in `src/lib/types.ts`; a subsystem's types
  in `<folder>/types.ts`.
- Model output is parsed with zod into the domain type; the tool JSON
  schema and the zod schema are kept next to each other in the same file so
  they cannot drift apart unnoticed.

## 5. Size signals

A file over ~700 lines is a split candidate. Today `src/interpret/tokenize.ts`
(≈900) and `src/assessments/decision.ts` (≈741) are over the line;
`src/salvage/assess.ts` (≈660) and `src/inspector/inspector.ts` (≈580) are
the two orchestrators, whose stages are the next split when they grow
again. Split along the section dividers already present, one file per
question, moving tests with the code. Where callers and SPEC citations name
the old file, leave it as a re-export facade (`src/salvage/knowledge.ts`)
rather than editing every import. Do this in its own commit, with no
behavior change, and update CLAUDE.md's routing table.
